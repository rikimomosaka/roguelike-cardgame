# ビジュアルアート仕様

更新日: 2026-08-08

## 基本方針

- ゲーム内で使用する人物、敵、召喚、背景、カード絵、レリック、ポーション、マップ、状態異常、演出用画像はすべてドット絵とする。
- 写実画、滑らかなデジタルペイント、ベクター風の滑らかな輪郭、3Dレンダーを完成素材として混在させない。
- UIをCSSで構築すること自体は許可するが、UI内へ配置するラスター画像は本仕様に従う。

## 画像制作基準

- 小さな基準解像度でピクセル単位に形を決め、最近傍補間で拡大する。
- 輪郭は硬いピクセルで構成し、アンチエイリアスやぼかしを使用しない。
- アイコンは限定パレットを基本とし、小さい表示でもシルエットだけで意味を判別できるようにする。
- 透過画像は背景を完全透過とし、輪郭に半透明の色縁を残さない。
- 拡大・縮小表示には `image-rendering: pixelated` を適用する。
- 既存画像を差し替える場合も、識別対象、主要色、向き、用途を維持する。

## 推奨基準サイズ

| 用途 | 制作時の基準 | 配布画像の目安 |
|---|---:|---:|
| 状態・トリガーアイコン | 60×60 | 180×180（3倍） |
| レリック・ポーション・マップアイコン | 60×60 | 180×180（3倍） |
| キャラクター | 作品内の共通グリッド | 整数倍 |
| 背景 | 画面比率に合う低解像度キャンバス | 最近傍補間した整数倍 |

サイズは固定契約ではない。重要なのは、制作グリッドと拡大倍率を明確にし、滑らかな再補間を行わないことである。

## キャラクターアニメーション

- キャラクターのモーションは、同じ大きさのセルを横一列に並べた透過PNGのスプライトシートとする。
- 現行主人公は高さ `256`、接地線 `y=255` を共通基準とする。待機セルは `128×256`。手足を横へ大きく伸ばすモーションは、キャラクターの縮小を避けるため横幅を拡張してよい。
- 待機モーションは8フレーム、`1024×256`。左から右へ再生し、8枚目から1枚目へ自然につながるループとする。
- 待機中の移動は呼吸、瞬き、髪・衣装の小さな揺れに留め、攻撃や被ダメージに見える大きな姿勢変化を混ぜない。
- 現行の攻撃・被ダメージは `192×256` を4フレーム横並びにした `768×256`。連撃のテンポを妨げないよう、攻撃は240ms、被ダメージは300msの1回再生とし、最後の有効フレームで止めてから待機へ戻す。OSの「アニメーションを減らす」が有効でも、この一回再生だけは同じ速度を維持する。
- 攻撃は「待機に近い構え → 右手を途中まで伸ばす → 画面右へ完全に突き出す → 余韻」、被ダメージは「驚く → のけぞり始める → 最大反動 → 戻り始める」の順とする。
- 未制作のモーションは待機または静止画へ戻し、欠けた画像を表示しない。
- シート全体の縦横比でキャラクター幅を決めてはならない。表示・影・当たり位置には1セルの縦横比を使う。
- フレーム送りはCSSの段階アニメーションで行い、フレーム間を滑らかに補間しない。
- `prefers-reduced-motion: reduce` では位置が動く待機上下動を止める。キャラクターが完全な静止画に見えないよう、瞬き・衣装差分のフレーム送りだけは低速で残す。

## 新規画像の受入条件

1. ドット絵として目視確認できる。
2. ゲーム内の最小表示サイズで識別できる。
3. 透過・寸法・参照パスが正しい。
4. 実ブラウザで読み込める。
5. 非ドット調の仮画像は完成素材と同じファイル名へ置かない。

## 現行資産の監査

2026-08-08時点で `src/Client/public` のPNG 105枚を確認した。実行時参照される97枚はすべてドット調であり、非ドット調だった新規状態アイコン4枚は本仕様へ合わせて差し替え済みである。ブラウザのfaviconも滑らかなSVGからドット絵PNGへ変更した。主人公の待機8フレーム、攻撃4フレーム、被ダメージ4フレームも、既存立ち絵と同じ16色・二値透過に正規化している。

敵・召喚の `imageId` は現在PNGへ接続されておらず、ゲーム画面ではCSSシルエットを表示する。将来立ち絵を接続するときも、本仕様に適合したドット絵だけを採用する。
