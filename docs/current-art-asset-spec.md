# 画像素材の規格と管理（現行）

2026-11-25 策定。ゲーム内の画像をすべて「本物のドット絵」（低解像度・少色・半透明なし）に置き換え、
規格・フォルダ・命名をそろえて、後から追加・差し替えしやすくする。

- 旧提案 [proposed-graphics-asset-pipeline.md](proposed-graphics-asset-pipeline.md) のうち、
  キャラのモーション規格とAI生成の流れはこの文書に取り込んだ。未決事項（§8）は引き続きそちらで扱う。
- キャラ個別の制作記録は `docs/art/characters/*.md`。

## 1. 基本ルール

1. **すべての画像はドット絵**。半透明なし（アルファは 0 か 255）、色数は種類ごとの上限以内。
2. **表示は整数倍**。各素材は「絵のドット数」と「表示倍率」を持ち、表示サイズ = ドット数 × 倍率。
   表示側は `image-rendering: pixelated` で拡大する（ぼかさない）。
3. **同じ種類の素材はキャンバスサイズを固定**。大きさの違いはキャンバスの中に描き込む（表示側で拡大縮小しない）。
4. **元画像（高解像度・編集用）と表示用は分ける**。
   - 元画像: `art/source/<種類>/<id>.png`（git 管理）
   - 表示用: `src/Client/public/assets/<種類>/<id>.png`（ビルドスクリプトが生成する。手で編集しない）
5. **コードから画像パスを直接書かない**。必ず `src/Client/src/presentation/assets.ts` の関数を通す。
   CSS は関数を呼べないので `/assets/...` を直接書く（主人公ごとの UI は CSS 変数 `--hero-ui-*` で渡す）。

## 2. 種類ごとの規格

倍率の「×2」は、絵の 1 ドットを画面の 2px で表示する。ステージ（1280×720）の基準倍率は ×2。

| 種類 | 表示用フォルダ | キャンバス（ドット） | 倍率 | 色数上限 | 備考 |
|---|---|---|---|---|---|
| 戦闘背景 | `backgrounds/battle/` | 640×360 | ×2 | 96 | 画面全体 |
| マップ背景 | `backgrounds/map/` | 640×360 | ×2 | 96 | |
| イベント背景 | `backgrounds/events/` | 480×320 | 表示枠に合わせる | 96 | 3:2 |
| 戦闘キャラ（主人公・味方・敵） | `actors/<区分>/<id>/` | 128×128 | ×2 | 32 | §3 |
| 立ち絵（カットイン等） | `portraits/` | 120×160 | ×2 以上 | 48 | 3:4 |
| 状態アイコン（バフ・デバフ） | `icons/status/` | 16×16 | ×1（拡大表示 ×2） | 16 | |
| 敵の行動予測アイコン | `icons/intent/` | 16×16 | ×2 | 16 | |
| システムアイコン | `icons/system/` | 16×16 | ×2 | 16 | 設定・地図・山札など |
| レリック | `icons/relics/` | 32×32 | ×1〜×2 | 24 | |
| ポーション | `icons/potions/` | 32×32 | ×1〜×2 | 24 | |
| マップのマス | `icons/map/` | 32×32 | ×2 | 24 | |

| 共通UI | `ui/common/` | 部品ごと | ×2 | 32 | |

## 3. 戦闘キャラ（128×128 共通キャンバス）

- 主人公・味方ユニット・敵すべて **128×128 ドット**、表示 ×2（256×256px）。
- **地面の線は 123 行目**（足の一番下のドットが 123 行目）。横の中心は 64 列目。
- **大きさはキャンバスの中で描き分ける**。小さい敵はキャンバスの下の方に小さく描く。
  目安の身長（ドット）: 小型 16〜40 / 中型 48〜80 / 大型 88〜120。主人公は約 76。16 ドット未満にはしない（形が読めない）。
- 敵・味方ユニットの身長と浮き具合は `art/source/actors/<区分>/<id>.json` の `height`・`lift`（地面から何ドット上げるか）。
  初期値は旧方式（heightTier で拡大縮小）での見た目の大きさから算出した（`tools/art-pipeline/init-actor-meta.mjs`）。
- 表示側は全キャラ同じ ×2。影の幅・効果の中心はビルドが測って `src/Client/src/presentation/generated/actor-assets.json` に書く。
- **飛んでいるキャラ**は、体の中心を 72 行目あたり（地面から約 50 ドット上）に置く。影は表示側が地面に描く。
- 正面方向: 主人公・味方は右向き、敵は左向き。
- モーション（主人公。敵は idle のみ必須）:

| ファイル | コマ数 | 時間 | ループ | 要点 |
|---|---|---|---|---|
| `idle.png` | 8 | 1200ms | する | 呼吸 1px・まばたき 1 コマ・髪や服の遅れ揺れ |
| `attack.png` | 6 | 600ms | しない | 3 コマ目が命中 |
| `attack_alt.png` | 6 | 600ms | しない | 同上（振りかぶり→振り下ろし等、attack と違う動き） |
| `skill.png` | 8 | 800ms | しない | 5 コマ目で技を放つ |
| `hurt.png` | 4 | 400ms | しない | 1 コマ目は赤フラッシュ |
| `down.png` | 6 | 720ms | しない | 最後のコマで止める |
| `stand.png` | 1 | — | — | idle の 1 コマ目（読み込み中・失敗時の代わり） |

- 各シートは 128×128 のコマを横に並べる。全コマで地面の線と横の中心をそろえる。
- 敵は `actors/enemies/<id>/stand.png`（1 コマ）から始め、動きは後から足す（無いモーションは表示側が stand で代用）。

## 4. キャラ専用UI・敵の汎用UI

戦闘画面下部の操作部品は、**主人公ごとに専用の絵**を持つ（キャラの色・モチーフに合わせる）。
文字（技名・数値）は HTML で重ねるので、画像には文字を入れない。

| ファイル（`ui/heroes/<id>/`） | キャンバス | 用途 |
|---|---|---|
| `combo.png` | 56×28 | コンボゲージ枠 |
| `tactical.png` | 44×28 | 戦技ボタン |
| `ultimate.png` | 44×28 | 奥義ボタン |
| `ready.png` | 76×32 | 準備完了（READY）ボタン |

- 押せない状態は表示側のフィルター（暗く・彩度を下げる）で表す。状態ごとの画像は作らない。
- 専用UIが無い主人公は `ui/heroes/default_frame/`（共通の枠）を使う。

敵の汎用UI（`ui/enemy/`）:

| ファイル | キャンバス | 用途 |
|---|---|---|
| `intent_plate.png` | 48×16 | 頭上の行動予測（アイコン＋数値）の下地 |
| `action_plate.png` | 64×16 | 行動時のカード名の札 |
| `action_button.png` | 24×12 | 「行動」（再生）ボタン |

## 5. 命名規則

- ファイル名・フォルダ名は **英小文字・数字・アンダースコア**（`a-z0-9_`）。ハイフン・大文字・日本語は使わない。
- `<id>` はゲームデータの ID と同じにする（レリック ID、ポーション ID、敵の imageId、キャラ ID など）。
- 状態アイコンは状態の ID（`strength`, `weak` など）。行動予測は `attack`, `attack_all`, `attack_random`, `block`, `buff`, `debuff`, `heal` など。
- 同じものの別案は作業フォルダ（`art-work/`、git 管理外）に置き、採用したものだけを `art/source/` に入れる。

## 6. 変換と生成の流れ

### 6.1 一括ビルド

```
node tools/art-pipeline/build-assets.mjs          # 全部
node tools/art-pipeline/build-assets.mjs icons/relics   # 種類を指定
```

- 種類ごとの設定（キャンバス・色数・変換方法）は `tools/art-pipeline/asset-rules.mjs` に一覧で持つ。
- 素材ごとの例外（色数を増やす、飛んでいる、身長など）は、元画像の横に `<id>.json` を置いて上書きする。
- 変換方法:
  - `pixelize`: 縮小（面積平均）→ 減色（k-means）→ アルファ二値化。背景・アイコン・カード枠。
  - `actor`: 不透明部分を切り出し → 指定の身長へ縮小 → 128×128 の地面の線（または空中の位置）へ配置 → 減色。
  - `native`: すでに規格どおりのドット絵（PixelLab で生成したもの・手直ししたもの）をそのまま検査して置く。
- ビルドは規格の検査も行う（サイズ・色数・半透明）。違反があれば失敗する。

### 6.2 新しい素材を足す

1. 元画像を `art/source/<種類>/<id>.png` に置く（高解像度の絵でも、規格どおりのドット絵でもよい）。
2. 必要なら `<id>.json` で例外を書く。
3. `node tools/art-pipeline/build-assets.mjs <種類>` を実行する。
4. コードでは `assets.ts` の関数（例: `relicIcon(id)`）で参照する。

### 6.3 変換で見た目が崩れた素材

縮小で潰れたもの（細かい模様のアイコンなど）は PixelLab で規格サイズのドット絵として描き直し、
`art/source/<種類>/<id>.png` を差し替えて `<id>.json` に `{"mode": "native"}` を書く。

## 7. 移行の進め方（2026-11-25 時点）

| 段階 | 内容 | 状態 |
|---|---|---|
| 1 | 規格・フォルダ・命名（この文書）、`assets.ts`、ビルドスクリプト | 済 |
| 2 | 既存画像を `art/source/` へ移し、全種類を一括変換。コードの参照を `assets.ts` に切り替え | 済（約 45MB → 1.6MB） |
| 3 | 変換結果を確認し、崩れたものを PixelLab で描き直す | 未 |
| 4 | 戦闘キャラを 128×128 共通キャンバスへ（敵 34 体・味方ユニット・主人公 4 人） | 済（セラ以外の主人公は旧素材の縮小で仮） |
| 5 | セラ専用の戦闘UI、敵の汎用UI を作って組み込む | 未 |
| 6 | 表示側を整数倍表示にそろえる（CSS） | 一部（全体を pixelated に。休憩画面の焚き火は ×4。アイコン類の表示サイズは未調整） |
