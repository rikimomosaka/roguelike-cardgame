# 画像素材の規格と管理（現行）

2026-11-25 策定。ゲーム内の画像をすべて「本物のドット絵」（低解像度・少色・半透明なし）に置き換え、
規格・フォルダ・命名をそろえて、後から追加・差し替えしやすくする。

- 旧提案 [proposed-graphics-asset-pipeline.md](proposed-graphics-asset-pipeline.md) のうち、
  キャラのモーション規格とAI生成の流れはこの文書に取り込んだ。未決事項（§8）は引き続きそちらで扱う。
- キャラ個別の制作記録は `docs/art/characters/*.md`。

## 1. 基本ルール

1. **すべての画像はドット絵**。半透明なし（アルファは 0 か 255）、色数は種類ごとの上限以内。
2. **表示は整数倍**。各素材は「絵のドット数」と「表示倍率」を持ち、表示サイズ = ドット数 × 倍率。
   表示側は `image-rendering: pixelated` で拡大する（ぼかさない）。
3. **同じ種類の素材はキャンバスサイズを固定**。大きさの違いはキャンバスの中に描き込む（表示側で拡大縮小しない）。
4. **元画像（高解像度・編集用）と表示用は分ける**。
   - 元画像: `art/source/<種類>/<id>.png`（git 管理）
   - 表示用: `src/Client/public/assets/<種類>/<id>.png`（ビルドスクリプトが生成する。手で編集しない）
5. **コードから画像パスを直接書かない**。必ず `src/Client/src/presentation/assets.ts` の関数を通す。
   CSS は関数を呼べないので `/assets/...` を直接書く（主人公ごとの UI は CSS 変数 `--hero-ui-*` で渡す）。

## 2. 種類ごとの規格

倍率の「×2」は、絵の 1 ドットを画面の 2px で表示する。ステージ（1280×720）の基準倍率は ×2。

## 3. 戦闘キャラ（128×128 共通キャンバス）

- 主人公・味方ユニット・敵すべて **128×128 ドット**、表示 ×2（256×256px）。
- **地面の線は 123 行目**（足の一番下のドットが 123 行目）。横の中心は 64 列目。
- **大きさはキャンバスの中で描き分ける**。小さい敵はキャンバスの下の方に小さく描く。
  目安の身長（ドット）: 小型 16〜40 / 中型 48〜80 / 大型 88〜120。主人公は約 76。16 ドット未満にはしない（形が読めない）。
- 敵・味方ユニットの身長と浮き具合は `art/source/actors/<区分>/<id>.json` の `height`・`lift`（地面から何ドット上げるか）。
  初期値は旧方式（heightTier で拡大縮小）での見た目の大きさから算出した（`tools/art-pipeline/init-actor-meta.mjs`）。
- 表示側は全キャラ同じ ×2。影の幅・効果の中心はビルドが測って `src/Client/src/presentation/generated/actor-assets.json` に書く。
- **飛んでいるキャラ**は、体の中心を 72 行目あたり（地面から約 50 ドット上）に置く。影は表示側が地面に描く。
- 正面方向: 主人公・味方は右向き、敵は左向き。
- モーション（主人公。敵は idle のみ必須）:

| ファイル | コマ数 | 時間 | ループ | 要点 |
|---|---|---|---|---|
| `idle.png` | 8 | 1200ms | する | 呼吸 1px・まばたき 1 コマ・髪や服の遅れ揺れ |
| `attack.png` | 6 | 600ms | しない | 3 コマ目が命中 |
| `attack_alt.png` | 6 | 600ms | しない | 同上（振りかぶり→振り下ろし等、attack と違う動き） |
| `skill.png` | 8 | 800ms | しない | 5 コマ目で技を放つ |
| `guard.png` | 6 | 720ms | しない | 防御効果を持つスキル用。2 コマ目で構えが固まる（ここでブロックが付く） |
| `cast.png` | 6 | 720ms | しない | それ以外のスキル用（強化・ドロー等）。3 コマ目で効果が出る |
| `hurt.png` | 4 | 400ms | しない | 1 コマ目は赤フラッシュ |
| `down.png` | 6 | 720ms | しない | 最後のコマで止める |
| `stand.png` | 1 | — | — | idle の 1 コマ目（読み込み中・失敗時の代わり） |

- 各シートは 128×128 のコマを横に並べる。全コマで地面の線と横の中心をそろえる。
- 敵は `actors/enemies/<id>/stand.png`（1 コマ）から始め、動きは後から足す（無いモーションは表示側が stand で代用）。

## 4. キャラ専用UI・敵の汎用UI

戦闘画面下部の操作部品は、**主人公ごとに専用の絵**を持つ（キャラの色・モチーフに合わせる）。
文字（技名・数値）は HTML で重ねるので、画像には文字を入れない。

| ファイル（`ui/heroes/<id>/`） | キャンバス | 用途 |
|---|---|---|
| `combo.png` | 56×28 | コンボゲージ枠 |
| `tactical.png` | 44×28 | 戦技ボタン |
| `ultimate.png` | 44×28 | 奥義ボタン |
| `ready.png` | 76×32 | 準備完了（READY）ボタン |
| `energy.png` | 32×32 | エナジーの枠（中央に数値） |
| `intent_plate.png` | 48×16 | 頭上の行動予告の下地（味方側。スロットのキャラごとに切り替え） |

- 押せない状態は表示側のフィルター（暗く・彩度を下げる）で表す。状態ごとの画像は作らない。
- 専用UIが無い主人公は `ui/heroes/default_frame/`（共通の枠）を使う。

共通UI（`ui/common/`）: 枠・パネル・ボタン・ゲージの溝・丸い部品。
`tools/art-pipeline/gen-ui-frames.mjs` が tokens.css の茶色・金でコードから描く（端の模様が 1 ドット単位でそろい、
9 分割で伸ばしても崩れない）。CSS は `src/Client/src/styles/pixel-frames.css` の 1 か所で当てる。

| 種類 | 画像 | 用途 |
|---|---|---|
| 窓（外へはみ出して描く） | `panel.png` 24×24 | ポップアップ・メニュー・山札一覧など、中の見出しが端まで塗る窓 |
| 大きいパネル | `panel.png` | 画面全体の外枠・一覧の外枠（額縁用に中を塗らない版もある） |
| 小さい箱 | `box.png` 12×12 | ラベル・数値・上部バーの項目 |
| へこんだ枠 | `inset.png` / `inset_active.png` 12×12 | 選択肢の行・アイコンの台・入力欄（ホバー・選択中は金の縁） |
| ボタン | `button*.png` 16×16 | 通常・ホバー・控えめ・危険・危険ホバー |
| ツールチップ | `tooltip.png` 12×12 | |
| ゲージの溝 | `bar.png` 6×6 | HP バー・コンボゲージ・スライダー。目立たないよう茶色の 1 ドットの縁だけ（中身は 2px 内側） |
| 丸い部品 | `node_*.png` / `slot_round.png` | マップのマス（状態・大きさごと）・ポーション枠 |

- 新しい部品に枠を付けるときは、`pixel-frames.css` の該当する種類のセレクタ一覧に足す。
- アニメーション（transition・animation・transform・filter・box-shadow）は各画面の CSS のまま。
  縁の色を変える演出は見えなくなるので、ホバー・選択中は「アクティブな枠」の画像に切り替える。
- キャラごとの色を使う枠（キャラ選択・図鑑のキャラ欄）と、水色の再生系UI（行動記録・待機通知）は意味のある色なので CSS のまま。

マップの道（マス同士をつなぐ線）は SVG のなめらかな線のまま。ドット単位で描く方式も試したが、斜めの道の段差が強すぎたので戻した（2026-11-25）。

敵の汎用UI（`ui/enemy/`）:

| ファイル | キャンバス | 用途 |
|---|---|---|
| `intent_plate.png` | 48×16 | 頭上の行動予測（アイコン＋数値）の下地 |
| `action_plate.png` | 64×16 | 行動時のカード名の札 |
| `action_button.png` | 24×12 | 「行動」（再生）ボタン |
| `energy.png` | 32×32 | 敵の行動再生中のエナジーの枠 |

### 4.5 カードイラスト

- 置き場所は `art/source/cards/art/<カードID>.png`（106×80）。ビルドすると表示用の一覧（`generated/actor-assets.json` の `cardArt`）に載り、
  `Card` コンポーネントが `cardId` からイラストを表示する。一覧に無いカードは従来どおり仮表示（ILLUST）。
- 絵の上下左右の端はマスクで隠れる。主役は中央の 80×58 に収める。
- 生成の指示文は `tools/art-pipeline/card-art-prompts.mjs` に一覧で持つ。
  - 初期デッキの「攻撃の基本」「防御の基本」（クラスごと）: 背景だけ生成し、そのクラスの主人公のモーションの 1 コマを等倍で合成する（膝上の構図）。
    「防御の基本」は guard（防御モーション）のコマを使う（4 人とも guard の 4 コマ目）。
  - クラス固有カード: 同じクラスに別のキャラが増える前提なので、プレイアブルキャラは描かない（道具・エフェクトが主役か、カードに合った無名の人物）。
- 流れ:
  1. `node tools/art-pipeline/gen-card-art.mjs --ids <id,...> --seeds 1,2` で候補を `art-work/cards/<id>_<seed>.png` に作る（1 枚 1 回分）。
  2. `node tools/art-pipeline/card-art-preview.mjs --out art-work/review/x.png <id>:<種類>:<所属>:<候補のパス> ...` で実際の枠に重ねて比べる。
  3. `node tools/art-pipeline/compose-card-art.mjs <id>=<seed> ...` で採用した候補を `art/source/cards/art/` に置く（背景のカードはここで合成。横の `<id>.json` に採用した seed を記録）。
  4. `node tools/art-pipeline/build-assets.mjs cards/art`。

## 5. 命名規則

- ファイル名・フォルダ名は **英小文字・数字・アンダースコア**（`a-z0-9_`）。ハイフン・大文字・日本語は使わない。
- `<id>` はゲームデータの ID と同じにする（レリック ID、ポーション ID、敵の imageId、キャラ ID など）。
- 状態アイコンは状態の ID（`strength`, `weak` など）。行動予測は `attack`, `attack_all`, `attack_random`, `block`, `buff`, `debuff`, `heal` など。
- 同じものの別案は作業フォルダ（`art-work/`、git 管理外）に置き、採用したものだけを `art/source/` に入れる。

## 6. 変換と生成の流れ

### 6.1 一括ビルド

```
node tools/art-pipeline/build-assets.mjs          # 全部
node tools/art-pipeline/build-assets.mjs icons/relics   # 種類を指定
```

- 種類ごとの設定（キャンバス・色数・変換方法）は `tools/art-pipeline/asset-rules.mjs` に一覧で持つ。
- 素材ごとの例外（色数を増やす、飛んでいる、身長など）は、元画像の横に `<id>.json` を置いて上書きする。
- 変換方法:
  - `pixelize`: 縮小（面積平均）→ 減色（k-means）→ アルファ二値化。背景・アイコン・カード枠。
  - `actor`: 不透明部分を切り出し → 指定の身長へ縮小 → 128×128 の地面の線（または空中の位置）へ配置 → 減色。
  - `native`: すでに規格どおりのドット絵（PixelLab で生成したもの・手直ししたもの）をそのまま検査して置く。
- ビルドは規格の検査も行う（サイズ・色数・半透明）。違反があれば失敗する。

### 6.2 新しい素材を足す

1. 元画像を `art/source/<種類>/<id>.png` に置く（高解像度の絵でも、規格どおりのドット絵でもよい）。
2. 必要なら `<id>.json` で例外を書く。
3. `node tools/art-pipeline/build-assets.mjs <種類>` を実行する。
4. コードでは `assets.ts` の関数（例: `relicIcon(id)`）で参照する。

### 6.3 変換で見た目が崩れた素材

縮小で潰れたもの（細かい模様のアイコンなど）は PixelLab で規格サイズのドット絵として描き直し、
`art/source/<種類>/<id>.png` を差し替えて `<id>.json` に `{"mode": "native"}` を書く。

## 8. 制作記録（2026-11-25）

- **描き直した状態アイコン**: 混乱・呪縛・動揺。縮小では暗く潰れていたため、PixelLab で 32×32 の
  「太い輪郭・単純な形」として描き、16×16 へ縮めた（`art-work/icons-regen/gen-status.mjs`、git 管理外）。
  束縛・攪乱・消耗・護衛も試したが、今の変換の方が分かりやすかったので差し替えていない。
  元の変換用画像は `art/source/_archive/icons_status/`。
- **小型の敵**（シラミ・スライム小・コウモリなど 16 ドット）は、表示倍率で見ると形が読めるので描き直していない。
- **セラ専用の戦闘UI**（`ui/heroes/default/`）: 紺の地・銀の縁・赤の差し色・残光の光ライン。
  PixelLab pixflux で規格サイズのまま各 3 案を生成して選んだ（`art-work/ui/gen-ui.mjs`、git 管理外）。
- **敵の汎用UI**（`ui/enemy/`）: 黒い石に深紅の縁。PixelLab は 32×32 相当より小さい面積を描けないので、
  2 倍の大きさで生成して規格サイズへ縮めた。札と行動予告の下地は CSS の border-image で 9 分割表示する
  （文字数で幅が変わっても端の装飾がゆがまない）。
- **セラの立ち絵**（`portraits/default.png`）: キャラ選択・カットイン用。PixelLab pixen の 128×160 を 120×160 に切り詰めた。
  旧キャラ（見習い冒険者）の立ち絵は `art/source/_archive/portraits/`。
  2026-11-27 に戦闘スプライトと同じ原画から作り直した（[striker_sera.md](art/characters/striker_sera.md)）。
- **ミレイユ・ユノ・リラの立ち絵と戦闘スプライト**（2026-11-28）: セラと同じ手順で作り直した。
  ChatGPT の全身原画（約 3.5 頭身）を縮小・減色して戦闘スプライトとアイコンにし、モーションは PixelLab で付けた。
  詳細は [heroes-rebuild-2026-11-28.md](art/characters/heroes-rebuild-2026-11-28.md)。
  前日の PixelLab だけの版（[heroes-rebuild-2026-11-27.md](art/characters/heroes-rebuild-2026-11-27.md)）は、顔つきが違ったため置き換えた。
