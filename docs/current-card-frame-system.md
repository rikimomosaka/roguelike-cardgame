# カードフレーム表示仕様

## レイヤー構成

カードは最背面から次の順に合成する。

1. 所属フレーム PNG（イラスト領域には名前帯と同じ所属色・質感の不透明 backing を含む）
2. タイプ別マスクで切り抜いたイラスト
3. カードタイプ枠 PNG（タイプ名を画像内に含む）
4. 所属別コスト台座 PNG と動的な現在コスト値。差分時は元コスト用の小台座も追加
5. カード名、効果文、選択・使用可否・伏策などの動的表示

所属色をカード全体の基調とし、Attack / Skill / Power などの違いは主にイラスト枠の四隅形状で示す。タイプごとにカード全体を赤・緑・紫へ塗り分けない。

レアリティはカード名の色だけで示す。Token 専用の見た目や `TOKEN` 表記は設けない。

## 所属フレーム

| 所属 | 主な意匠 |
|---|---|
| Striker | 剣、赤、銀 |
| Guardian | 盾・装甲、紺、銀 |
| Tactician | 角張った構造、緑、鈍い金 |
| Enhancer | 穏やかな曲線、紫、鈍い金 |
| Universal | 象牙、銀、暗色の名前欄 |
| Curse | 黒鉄、亀裂、暗い紫 |

カードタイプが Curse の場合は、カード定義上の所属より Curse フレームを優先する。所属が未指定または未知の場合は Universal を使う。

Token と Summon は生成元カードの実効所属を引き継ぐ。Universal のカードから生成される場合、または生成元を特定できない場合は Universal とする。

所属フレームのイラスト領域は透明にしない。タイプ枠の開口形状が所属枠より内側へ入ってもページ背景や黒い下地が露出しないよう、生成時に所属枠の最大閉鎖開口を検出し、左右と下へ16px、上だけ25px膨張した範囲へ所属別 backing を敷く。上方向を広くするのは旧イラスト内枠の水平ハイライトが開口から25px上まで残るためであり、左右まで25pxへ広げて所属外周を削らないための非対称処理である。backing は各所属の名前帯にある安全な地色領域 `x=100..459, y=42..93` を実画像から採取し、継ぎ目が出にくい鏡面反復で全面へ延長する。中央部では置換開始行 `y=94` に同じx座標の `y=93` をそのまま接続し、色・模様の位相を連続させる。このため Striker は赤、Guardian は青、Tactician は緑、Enhancer は紫、Universal と Curse は各名前帯固有の暗色と実際の材質模様をそのまま引き継ぐ。この形状追従マスクで生成元に残る旧イラスト内枠も除去するが、カード外周・名前枠・`y=500` 以降の本文枠は元画像の画素を完全に維持する。

## カードタイプ枠

内部タイプと表示文字の対応は次の通り。

| 内部タイプ / ファイル名 | 画像内の表示 |
|---|---|
| `attack` | `ATTACK` |
| `skill` | `SKILL` |
| `power` | `POWER` |
| `unit` | `SUMMON` |
| `status` | `STATUS` |
| `curse` | `CURSE` |

`unit` は既存 API とファイル名を壊さないための内部名に限る。プレイヤー向けには常に `SUMMON` と表示し、`UNIT` や `TOKEN` は表示しない。

全タイプで次を共通契約とする。

- 上辺は同じ高さの水平線とし、中央を上へ突き出さない。
- ラベル台座は現在の Skill と同じ細い寸法・形・文字サイズ・基線に揃える。
- タイプ差は装飾記号の追加だけでなく、開口そのものの輪郭で表す。Attack は鋭い内向き斜角、Skill は大きい丸角、Power は重い段付き角、Summon は門型、Status は非対称な継ぎ、Curse は棘と亀裂を使う。
- 非 Curse タイプは暗い鋼・銀・控えめな金を基本とし、タイプ色で所属色を上書きしない。
- イラストは通常の正方形または長方形画像を供給し、タイプ別 mask が最終形状へ自動的に切り抜く。

## 560×784 アセット契約

所属フレーム、タイプ枠、イラスト mask は `560×784` の共通キャンバスを使う。ランタイムでは `112×156.8 CSS px` へ縮小する。

| 用途 | 560×784 上の領域 |
|---|---:|
| タイトル表示 | およそ `x=110..450, y=20..130`（カード中心 `x=280` に対して左右対称） |
| タイプ枠の配置枠 | `x=30..530, y=125..500` |
| タイプ枠の実画素外形 | およそ `x=37..522, y=131..493` |
| 全 mask 共通の重要被写体 | `x=120..445, y=155..405` |
| 本文表示 | およそ `x=15..545, y=500..759` |
| 現在コスト | 配置箱は `28×28 CSS px` でカード左上から左へ7px・上へ2px張り出す。可視台座画像は中央基準の `30×30 CSS px` で、外縁は左へ8px・上へ3px張り出し、20pxの現在値を表示 |
| 元コスト台座 | `22×22 CSS px`。現在値と異なる時だけ、中心を揃えて現在コスト配置箱の上端から27pxに配置 |

本文領域はフレーム内側へ左右8pxずつ空けた実幅 `94 CSS px` とする。上余白は `4px` として本文全体を旧配置より2px下げる。1行は標準行間、2〜3行は `1.35`、4行は `1.08`、5行は `1.0` の行間とし、5行だけ文字を縦方向へ `0.88` 倍して、文字の横幅を変えず最大5行を収める。カード名は左右へ同じ22pxの予約域を置き、コストとの重なりを避けながらカード全体と同じ中心へ揃える。

現在コストは所属別台座上へ表示し、元コストより低い場合は黄色、高い場合は青色、同じ場合は白色にする。現在値の配置箱は28pxのまま、台座画像だけを中央基準で30pxへ拡大し、20pxの数字を中心から2px上へ光学補正する。拡大後も名前と重ならないよう表示全体を1px左へ寄せる。現在値と異なる時だけ、同じ所属の22px台座と13pxの灰色の元コストを直下へ表示する。元台座は現在値の配置箱に対して上から27pxの位置へ置き、実画素同士がほぼ隙間なく接するようにし、数字だけを中心から1px上へ補正する。小さい数字を潰さないため打ち消し線は使わない。カード本体は台座の張り出しを切り取らず、スクロール一覧は先頭カード用の左上余白を確保する。本文はぼかしのない上下左右1pxの黒縁を持つ。各行は小数精度の実幅で判定し、文字本体を左右2px内側へ収めることで、黒縁の外にも1pxの空きを残す。再演・伏策の条件行も表示文として句点 `。` で終え、終端の全角字形が右縁へ寄りすぎないよう同じ幅判定へ含める。

## アセット配置

```text
src/Client/public/cards/frames/
├── affiliations/  # 560×784、6所属
├── types/         # 560×784、6タイプ
├── masks/         # 560×784、6タイプのイラスト開口mask
└── costs/         # 128×128、現在値と差分時の元値に使う6所属の台座
```

## 生成元と再生成

本番分割元は次の単色クロマ版アトラスである。

- `artifacts/card-frame-production-atlas-v5-assembled-chroma.png`
- `artifacts/card-type-plaques-v1-chroma.png`（全タイプで同一形状のラベル台座）
- `artifacts/card-type-frame-shapes-v2-chroma.png`（3列×2行のタイプ形状上書き）

アトラスは5列×4行で、次の固定スロットを持つ。

| 行 | C1 | C2 | C3 | C4 | C5 |
|---|---|---|---|---|---|
| 1 | Striker所属 | Guardian所属 | Tactician所属 | Enhancer所属 | Universal所属 |
| 2 | Curse所属 | Attack枠 | Skill枠 | Power枠 | Summon枠 |
| 3 | Status枠 | Curse枠 | Strikerコスト | Guardianコスト | Tacticianコスト |
| 4 | Enhancerコスト | Universalコスト | Curseコスト | 空 | 空 |

タイプ形状上書きアトラスは3列×2行を均等分割し、次の固定順序で配置する。

| 行 | C1 | C2 | C3 |
|---|---|---|---|
| 1 | Attack | Skill | Power |
| 2 | Summon (`unit`) | Status | Curse |

各セルは外周まで連続した不透明の明るいシアンを背景とし、枠はセル境界に触れないよう十分な余白を持たせる。6枠とも開口を閉じ、上辺をタイトル領域へ突き出さず、下中央には共通ラベル台座を合成できる接続部を残す。

背景は偽の市松模様ではなく、外周まで連続した不透明の明るいシアンである。分割ツールは四隅から実際の背景色を推定し、外周につながるクロマ領域と大きな閉鎖開口だけを透明化する。銀・白の内側ハイライトは保持し、低alphaの背景混色は除染する。透明ピクセルは `RGBA(0,0,0,0)` にする。

```powershell
dotnet run --project .\tools\CardFrameAtlasTool\CardFrameAtlasTool.csproj -- `
  .\artifacts\card-frame-production-atlas-v5-assembled-chroma.png `
  .\src\Client\public\cards\frames `
  .\artifacts\card-type-plaques-v1-chroma.png `
  .\artifacts\card-type-frame-shapes-v2-chroma.png
```

第4引数は任意であり、省略時は従来どおり5列×4行の本体アトラス内にあるタイプ枠を使う。指定時は所属6枚とコスト6枚を本体アトラスから、タイプ6枚とmask 6枚だけを3列×2行の上書きアトラスから生成する。

ツールは6枚の台座を同じ `302×66`、同じalpha輪郭、同じ基線へ正規化し、各タイプ枠の同じ座標へ焼き込む。その後、24ファイル、スロット対応、所属枠の不透明イラスト backing、タイプ枠の上端・下端、台座輪郭、mask共通安全領域、透明角、孤立ノイズ、クロマ残りを検証する。タイプ形状上書きを指定した場合は、全15組のタイプmaskについて開口の排他的差分が和集合の2%以上あることも必須とする。さらにcommit直前に、旧イラスト内枠の除去マスク内が名前帯から決定的に生成した所属別テクスチャと完全一致し、全画素が不透明で、旧 `RGBA(8,10,13,255)` backing が1画素も残らず、単色化せず64色以上の材質情報を保っていることを検証する。タイトル接続部 `x=120..439, y=80..140` は隣接行間の1画素平均RGB距離を計測し、最大5.00以下でなければ水平シームとして生成を拒否する。マスク外は正規化済み入力と完全一致させ、本文枠と透明外周が未変更であることも画素単位で検証する。続いてstaging内の6タイプmaskの開口和集合を作り、その全画素がstaging内の6所属フレームすべてで完全不透明（alpha 255）であることも検証する。将来タイプ開口が現在のbackingを越えた場合や、除去範囲が外周・名前帯・本文枠へ漏れた場合は本番素材を置き換えずに失敗する。3引数の従来入力でも同じ接続検証を行い、差分値を計測・出力する。出力は一時領域へ生成し、全検証に成功した場合だけ本番24枚を反映する。
