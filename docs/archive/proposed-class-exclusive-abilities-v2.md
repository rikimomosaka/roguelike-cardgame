# クラス固有能力 提案仕様 v2

> **アーカイブ（2026-11-27 移動）:** 採用された能力（乗勢・終撃・残光・再演・堅持・護衛・守勢・攪乱・伏策・連環・余韻・共鳴）は実装済み。現行の要約は [current-class-card-abilities-spec.md](../current-class-card-abilities-spec.md) と [current-battle-status-spec.md](../current-battle-status-spec.md)。細かい処理順はこの文書の採用案どおりに実装されているが、食い違いがあれば実装（テスト）が正。
> 現行仕様は `docs/current-*.md` が正本。この文書は経緯の記録として残している。


最終更新: 2026-08-21

この文書は、クラス固有能力の名称・挙動・処理順を相談するための案であり、まだ実装仕様として確定していない。既存カードはすべて検証用仮データとして扱う。

今回の整理では、採用方向が定まった能力と、再設計する能力を明確に分ける。再設計対象を無理に別案で埋めず、まず残す能力の境界を固める。

ここでいう「クラス固有」は取得プールとカード配布上の方針であり、Coreの効果機構そのものへクラス制限を設ける意味ではない。別クラス、Universal、敵、レリック、ポーションから同じ効果を利用するデータも技術的には作成可能にする。

## 1. 現在の採否

| クラス | 採用方向 | 再設計・廃案 |
|---|---|---|
| Striker | 乗勢X（条件キーワード）、終撃（キーワード）、残光（バフ） | 旧「連携」という名称・成立判定 |
| Guardian | 堅持（バフ）、護衛（バフ）、守勢（バフ） | 旧パーティ共有防御としての陣壁、Guardian全員への標準持越し能力、旧専用資源としての守勢 |
| Tactician | 攪乱（デバフ）、伏策（キーワード）、連環（バフ） | 計画領域、偵察、遅滞。号令は保留案 |
| Enhancer | 余韻（バフ）、共鳴（バフ）、回復・復活の主担当 | 伴奏、転調、触媒、調薬／備薬 |

## 2. Striker

### クラスの判断軸

自分でコンボを組み、終撃でそのコンボを確定し、確定したAttackカード群の効果を残光で繰り返す。単純な高打点クラスではなく、「どのAttackを1つのコンボへ含めるか」「いつ終撃するか」「残光をいくつ準備するか」を判断する。

### 2.1 乗勢X

分類: **Striker固有キーワード能力**

旧称: `連携`

> 効果の実行時、自身のこのターンの最大コンボがX以上であれば適用される。

カード上では `乗勢3：敵単体に11アタック。` のように、条件と条件付き効果を同じ行へ表示する。

「連携」という名前では、能力そのものがコンボを繋いでいるように読める。しかし実際にコンボを成立させるのはプレイヤーのカード選択であり、この能力はプレイヤーが作った勢いに乗って追加効果を発生させる。そのため正式名を `乗勢`（じょうせい）とする。

規則:

- 判定値は `現在コンボ` ではなく、そのparticipantの `このターンの最大コンボ` を使う。
- 実カード使用では、通常どおりコンボと最大コンボを更新してから効果列を処理する。そのカード自身によって最大コンボがXへ到達した場合、そのカードの乗勢Xも成立する。
- 終撃は現在コンボを0へ戻すが、最大コンボは維持する。そのため一度Xへ到達すれば、そのターン中は終撃後も乗勢Xが成立する。
- 最大コンボは正式なターン開始時に0へ戻る。前ターンの達成値は参照しない。
- 残光と再演はコンボを増やさないが、効果を再実行する時点の最大コンボで乗勢Xを再判定する。最大コンボX以上なら追加部分も実行し、未満なら実行しない。
- 1枚のカードに異なる閾値の乗勢を複数記載できる。各条件ブロックを独立して判定する。
- participantごとの最大コンボだけを参照し、他者の最大コンボは使わない。
- tooltipには `乗勢3：成立` または `乗勢3：最大コンボ2のため不成立` のように現在の状態を表示する。
- 乗勢は追加効果の条件であり、コンボを維持する能力ではない。乗勢を持っていても通常のコンボ条件を満たさなければ現在コンボは途切れる。

### 2.2 終撃

分類: **Striker固有キーワード能力**

> 効果の適用後、このカードを含むこのコンボ中の全てのアタックカードを残光としてこのターン中保存し、現在コンボを0にする。

処理の大枠:

1. 通常どおりカード使用可否、コスト支払、使用回数、コンボ継続を確定する。
2. 終撃カード自身を含めて現在コンボ、最大コンボ、コンボゲージを更新する。
3. 更新後の現在コンボを `consumedCombo` として保存する。
4. 終撃カードの本体効果と選択処理を完了する。
5. 終了したコンボに含まれるAttackカードを使用順に記録する。終撃カード自身がAttackなら記録へ含める。
6. 現在コンボ、直前の元コスト、Wild使用済み状態、次カードへのコンボ保護をリセットする。

記録するもの:

- そのコンボに含まれたAttackカードのID、強化状態、表示名、使用順。
- 各Attackカードが持つ効果列。
- 元カードを再表示するために必要な表示情報。
- 乗勢やコンボ数条件を含む、条件付き効果の定義そのもの。

記録しないもの:

- カードinstanceの現在zone。
- 元の対象actorそのもの。
- 元のランダム抽選結果。
- コスト支払や使用回数の増加といったカード使用処理。

境界:

- 終撃は必ず現在コンボを0へ戻す。
- 最大コンボと獲得済みコンボゲージは維持する。同じ小コンボを繰り返してゲージを再獲得することはできない。
- 1枚目に終撃を使用した場合も、消費コンボ1として終撃自体は成立する。
- 同じターンに複数回終撃した場合、残光が参照する記録は最後に終撃したコンボで上書きする。
- 記録はターン終了時に消去する。
- 終撃カードには原則として `このカードを含むコンボ数がX以上なら` という効果を持たせ、十分なコンボを組んでから使う価値を作る。
- 上記はコンテンツ設計上の原則であり、終撃キーワード自体はコンボ数が足りなくても現在コンボを終了する。

条件付き効果は、元の使用時に成立した部分だけでなく定義全体を記録する。残光または再演による再実行時に条件を改めて判定し、その時点で条件を満たしていない部分は実行しない。

例えば `敵単体に5アタック。コンボ3以上なら、さらに10アタック。` を再実行する時点でコンボ3未満なら、5アタックだけを実行する。コスト不足、使用回数上限、使用禁止、必要カード枚数など「カードを使用できるかどうか」の条件は無視する。

### 2.3 残光

分類: **Striker固有バフ**

> 自身の攻撃終了時、終撃によって保存された全ての効果を使用順にX回再実行し、残光が消滅する。

発動時点:

- 全員READY後の攻撃解決中、そのキャラクターが元から予約していた攻撃処理を終えた直後に発動する。
- 元から予約したattackが0件でも、そのキャラクターの解決slot終端で判定し、残光を空打ちとして消費できるようにする。
- 次の味方または敵の攻撃順へ移る前に、残光の処理を全て完了する。
- Planning中にカードを再使用する能力ではない。

処理:

1. 発動時点の残光Xを再実行回数としてsnapshotし、残光を先に0にする。
2. このターン最後の終撃記録を読み取る。
3. 記録されたAttackカードを使用順に1枚ずつ画面中央へ表示し、そのカードの効果列を再実行する。
4. その1周で作られたattackを解決し終えてから、次の1周へ進む。
5. snapshotしたX回分が終わるまで、同じ終撃記録を最初から繰り返す。

終撃記録がない場合:

- そのターンに終撃していなくても、発動時の残光は全て空打ちとして消費する。
- 前ターンの記録は参照しない。
- 表示上は `再実行できる終撃記録なし` と分かるようにする。

再実行するもの:

- Attackカードが持っていた効果を、attackだけに限定せず可能な限り全て再実行する。
- attack、block、buff、debuff、heal、draw、discard、コスト変更、召喚なども、そのカードの効果列に含まれていれば対象になる。
- attackによって生じるOnHit、反射、吸血、Barrierなどの通常戦闘処理も発生する。

再実行しないもの:

- エナジーやコンボゲージの支払。
- 元カードの手札・捨札・除外・Power領域間の移動。
- カードの使用回数カウント。
- コンボ、最大コンボ、Wild／SuperWild、終撃、喪失、待機、伏策、再演など、カードを「使用したこと」に伴うキーワード処理。
- 乗勢は効果部分の条件なので例外とし、残光処理時点の最大コンボで再判定する。
- OnPlayCardやOnComboなど、カード使用そのものを条件とするtrigger。

対象決定:

- 元のカード使用時の対象は引き継がない。
- Singleは残光処理時点の使用者の現在対象を使う。対象不在時は通常の再対象規則に従う。
- Randomは残光の各再実行ごとに再抽選する。
- Allは残光処理時点の全対象へ適用する。
- 効果量が現在HP、手札枚数、状態変化などを参照する場合、残光処理時点の値で再評価する。

ターン1回制限との関係:

- 元カードが `1ターンに1度` でも残光は実行できる。
- 残光はカード使用ではないため、元カードの使用回数を増やさず、使用上限によって拒否されない。
- ドローを含むAttackカードも再実行できるが、残光スタック数によって実行回数が有限であることを前提とする。

見た目:

- 手札や捨札から移動させず、何もない場所から半透明の元カードが画面中央へ連続表示される。
- 通常のカード使用とは異なる残像表現を付ける。
- 各カードの表示後、その効果を処理してから次の記録カードを表示する。

安全境界:

- 残光で実行した効果を、新しい「使用カード履歴」や「終撃コンボ記録」へ追加しない。
- 残光で終撃キーワードを再処理しない。
- 発動開始時の残光を先に0にするため、処理中に新しく得た残光は現在の再実行回数へ合流しない。再入防止flagも持たせる。
- 終撃記録へ入るAttackカードが残光を直接付与すると、次ターン以降まで連鎖し得る。初期実装ではこの構成をコンテンツ検証で拒否する案を推奨する。
- participantごとの1回の解決で処理できる再実行カード数・effect数に安全上限を持たせる。
- 手札や対象等を選ぶ `choose` 効果も再実行する。選択部分そのものをコピーするため、残光処理中に新しい選択を要求し、選択完了まで共有解決を一時停止する。
- CPUが残光を処理する場合は、通常のCPU選択規則で即決する。人間の場合は本人だけが選択を行い、他participantは解決再開を待つ。

### 2.4 再演

分類: **全クラスで利用可能な汎用キーワード能力**

> 再演条件を満たし、この戦闘中に最後に効果の解決を完了した自身のカード1枚の効果を再実行する。

例:

- `再演：3コスト以下のスキル。`
- `再演：アタック。`
- `再演：元コスト1のカード。`

規則:

- 再演を持つ現在カードより前に、自分が実際に使用したカード履歴だけを検索する。
- 条件にはカード種別、元コスト、支払コスト、キーワードなどを指定できる形を想定する。
- 条件に合う最後の1枚だけを再実行する。
- 対象がなければ空打ちとなるが、現在カードの使用自体は成功する。
- 残光と同じ効果再実行基盤を使い、対象・ランダム・現在値を再実行時に決め直す。
- コスト、カード移動、使用回数、コンボ、カード使用キーワード、OnPlayCard等は再実行しない。
- 再演キーワード自体は効果列ではないため、再演したカードに再演が記載されていても連鎖再演しない。
- 1ターン使用制限のあるカードも再演でき、使用回数は増加しない。

残光との違い:

| | 残光 | 再演 |
|---|---|---|
| 分類 | Striker固有バフ | 汎用キーワード |
| 対象 | 最後の終撃コンボに含まれる全Attackカード | 条件に合う最後の1カード |
| 回数 | 残光の現在値だけ繰り返す | 記載された再演1回 |
| 主な発動時点 | 本人の攻撃解決終了後 | 再演を持つカードの効果処理中 |
| 記録元 | 終撃で確定したコンボ | このターンのカード使用履歴 |

## 3. Guardian

### クラスの判断軸

余らせたブロックを次ターンへ持ち越し、そのブロックを味方の不足分へ回し、防ぎ切ることでコンボゲージを得る。旧案の共有防御値と対象指定式の護衛は統合し、Guardian自身のBlockを実際に融通する形へ変更する。

### 3.1 堅持

分類: **バフ**

> ターン終了時に消滅するブロックの50%を次のターンに持ち越す。ターン終了時に堅持が1減少する。

堅持はGuardianクラス全員の標準能力にはしない。Guardianカードから付与できるほか、例えば特定のGuardianキャラクターだけが「ターン開始時に自身へ堅持1を付与する」という特性を持つことで、そのキャラクターは実質的に毎ターンBlockを持ち越せる。

規則:

- 堅持XのXは残りターン数であり、正式なターン終了時に1減少する。
- 正式なターン終了時、通常のBlock消去直前に処理する。
- 最初に既存バフ `堅牢` で持ち越すBlockを確定する。
- 堅牢で持ち越されず、本来失われる残りBlockの50%を切り捨てで追加保持する。
- 堅牢が現在Blockを全て持ち越す場合、堅持による追加保持は0になる。
- Blockを新しく得る効果ではないため、敏捷やBlock獲得triggerを発動しない。
- 持ち越したBlockは次ターンの通常Blockと同じものとして扱い、追加Blockと合算できる。
- ターン終了時減少型Buffであるため、余韻による保護対象になる。

計算:

- `B = ターン終了時の現在Block`
- `F = min（B, 堅牢X）`。堅牢がなければ0。
- `L = B - F`。通常なら失われるBlock。
- `堅持による追加持越し = floor（L ÷ 2）`
- `最終持越し = F + floor（L ÷ 2）`

例:

- Block10、堅牢0なら、堅持で5を持ち越す。
- Block10、堅牢7なら、堅牢で7、失う予定の3から堅持で1、合計8を持ち越す。
- Block10、堅牢10なら全て堅牢で持ち越すため、堅持による追加は0。

### 3.2 護衛

分類: **Guardian向けバフ**

> アタックによって味方が受けるダメージを、自身のブロックで可能な限り防ぐ。ターン終了時に護衛が1減少する。

旧案との違い:

- 特定の1人を事前指定しない。
- hitごとに護衛を消費しない。
- ダメージ自体をGuardianのHPへ移さない。
- GuardianのBlockを、他者の不足Blockとして実際に支払う。

1hitの処理順案:

1. 本来の対象者自身のBlockで防ぐ。
2. まだHPへ届くダメージがあれば、生存中かつBlockを持つ護衛者を敵に近い前衛順で確認する。
3. 最前衛の護衛者が自身のBlockを可能な限り支払う。
4. まだ不足があれば、次の護衛者が同様に支払う。
5. 全護衛者の処理後もHPダメージが残る場合、対象者本人のBarrierを判定する。
6. Barrierでも防げなければ、対象者本人のHPを減らす。

規則:

- 護衛XのXは残りターン数として扱い、正式なターン終了時に1減少する。
- Xが1以上である限り、そのターン中の回数制限なしでBlockを融通する。
- 敵由来のattackだけが対象。毒、火傷、自傷、反射、HP直接減少には働かない。
- 対象者はプレイアブルキャラでもメイトでもよい。
- 護衛者自身の被弾には自分の護衛を使わない。
- 複数護衛者の優先順位は、表示配列順ではなく明示された前衛距離順で固定する。同距離時のtie-breakも固定する。
- 全体攻撃では各対象の正式な被弾順に処理し、その時点で残っている護衛者のBlockを使う。先に守った味方によって、後の味方へ使えるBlockが減る。
- 護衛者が支払うのはBlockだけであり、護衛者のBarrierやHPは消費しない。
- 対象者のBarrierより護衛が先に働く。
- ターン終了時減少型Buffであるため、Enhancerの余韻による保護対象になる。

護衛Blockを支払ってもなおHP減少が残る場合だけBarrierが発動する。その時点では対象本人と護衛者の利用可能なBlockを使い切っているため、戻すBlockは存在しない。護衛で全て受け切れた場合はBarrier自体が発動しない。

### 3.3 守勢

分類: **Guardian向けバフ**

> 自身のブロックを使って敵のアタックを完全に防いだ時、コンボゲージを1得る。ターン終了時に守勢が1減少する。

規則案:

- 守勢XのXは残りターン数であり、正式なターン終了時に1減少する。
- 自身が直接受けた攻撃を、自身のBlockだけでHP減少0にした場合に発動する。
- 護衛によって味方の不足分を支払い、その支払いによって残りダメージを0にした場合も発動候補とする。
- Barrierによって最終的に0になった場合は、「Blockで防ぎ切った」ことにならないため発動しない。
- 他の護衛者や対象本人のBlockだけで防ぎ切り、自身のBlockを使わなかった場合は発動しない。
- 停滞中は通常規則どおりコンボゲージを得られない。
- コンボゲージの上限を超えて増えない。
- 攻撃解決中に得るため、原則として次のPlanningから利用する。
- ターン終了時減少型Buffであるため、余韻による保護対象になる。
- 判定は1hit単位。多段攻撃を全hit完全Blockすれば、hit数と同じだけコンボゲージを得られる。
- 護衛に複数人がBlockを支払い、最後の護衛者の支払いで残りダメージが0になった場合は、その最後の護衛者だけが「完全に防ぎ切った」として守勢を発動する。

## 4. Tactician

### 現在の状態

旧案の `計画領域`、`偵察`、敵行動を次ターンへ送る `遅滞` は採用候補から外す。タクティシャンは、カードをあらかじめ除外へ仕込む `伏策` と、複数ターンにまたがってコンボを設計する能力を中核にする。

### 4.1 攪乱

分類: **デバフ**

> 自身の全てのアタックをランダム攻撃に変更する。ターン終了時に攪乱が1減少する。

範囲優先順位:

1. 拡散が有効なら `All`。
2. 拡散がなく、攪乱が有効なら `Random`。
3. どちらもなければ元のSingle／Random／Allを使う。

規則案:

- 元がSingleでもAllでもRandomへ変更する。元からRandomなら変化しない。
- multi-hitはhitごとに、その時点の有効対象から独立して再抽選する。同じ対象へ連続してもよい。
- 元の固定対象指定は無視する。
- プレイヤー、メイト、敵のいずれにも適用できる汎用Debuffとする。
- 攻撃予定表示は攪乱の増減に応じて即座にRandom表示へ更新する。
- 通常Debuffとして耐性で拒否できる。
- Xは残りターン数とし、正式なターン終了時に1減少する。

旧案の「全体hitをX回だけRandomへ変換する」方式は廃止する。

### 4.2 伏策:発動条件

分類: **Tactician固有カードキーワード**

> 使用時は効果が実行されず、発動待ちとして除外する。伏策条件を満たした時に効果を実行し、捨札へ移動する。

表記例:

- `伏策:ターン開始時`
- `伏策:相手の攻撃時`
- `伏策:3コンボ達成時`

使用時の処理:

1. コスト、カード使用回数、使用禁止、コンボ、OnPlayCardなど、伏策カードを実際に使用する処理は通常どおり行う。
2. その場ではカードの効果列を1つも実行しない。
3. 捨札、Power領域、召喚保持など通常の移動先より伏策を優先し、カードを `発動待ち` の印付きで除外へ置く。
4. 発動条件と伏策を置いた順番を、そのcard instanceに保持する。

発動時の処理:

1. そのタイミングで条件を満たす発動待ち伏策をsnapshotする。
2. 伏策を置いた順に、各カードを画面中央へ表示する。
3. 各カードの効果列を先頭から全て実行する。対象、乱数、数量、乗勢などの条件は発動時の状態で決め直す。
4. 選択式効果があれば、発動時点の候補からその都度選択する。人間所有者なら現在の解決を一時停止して本人が選び、CPU所有者ならCPUが即決する。
5. 通常は発動後に除外から捨札へ移す。`喪失` も持つ場合は除外に留め、発動待ち印だけを外す。

タイミングの初期定義:

- `ターン開始時`: 伏策を置いた後に訪れる正式なターン開始時、通常のターン開始時trigger列の中で発動する。
- `相手の攻撃時`: 多段を含む敵Attack 1行動につき1回、追撃と最初のhitより前、かつ範囲・対象・最終ダメージを決める前に発動する。攪乱、脱力、味方Blockなどをその攻撃全体へ間に合わせられる。
- `Xコンボ達成時`: 所有participantの現在コンボが、実カード使用によってX未満からX以上へ更新された直後に発動する。終撃後に新しいコンボを組んで再びXへ到達すれば、別の発動機会になる。伏策カード自身の使用によってXへ到達した場合も、除外へ置いた後に発動判定を行う。残光・再演はコンボを進めないため、このtrigger自体は発生させない。

喪失・待機との優先順位:

- `伏策 + 喪失`: 使用時は伏策として除外へ置く。発動後も捨札へ戻らず除外に留まるが、発動待ち印を失うため二度と自動発動しない。
- `伏策 + 待機`: 伏策を優先する。手札に残さず除外へ置き、発動後は通常どおり捨札へ移る。待機による次回発動は行わない。
- `伏策 + 喪失 + 待機`: 伏策として除外へ置き、1回発動した後は発動待ちでない除外カードとして残る。

境界:

- 発動はカードの再使用ではない。コスト、使用回数、コンボ更新、OnPlayCard、伏策・喪失・待機などのカードキーワードは再処理しない。
- 伏策を持つAttackカードも、実際に使用したAttackとして現在コンボのカード履歴へ入る。終撃で保存され、残光または再演の対象になった場合は、伏策キーワードを再処理せず効果列だけをその場で実行する。元のcard instanceは別途、除外で発動待ちを続ける。
- 同じタイミングに複数枚あれば、発動待ちになった順で処理する。途中の効果で盤面が変わった場合、後続伏策は変更後の状態を見る。
- 発動開始時に対象集合をsnapshotし、発動中に同じタイミングを再度発生させても同じ伏策を再帰発動させない。
- 発動条件が来なければ、ターンをまたいで除外に残り続ける。
- 発動待ち伏策も通常の除外カードとして、除外回収、強化、コスト変更、領域移動などの対象になる。
- 別の効果によって除外以外の領域へ移動した瞬間、発動待ち状態を失う。その後、通常の効果で除外へ戻されても自動では再待機しない。伏策カードとしてもう一度実際に使用した場合だけ、改めて発動待ちになる。
- 除外内で強化された場合は待機を維持し、発動時には強化後の効果列を使う。コスト変更は待機中の発動には影響しないが、後に回収して使用する場合のcard instance情報として残る。
- 除外表示では、通常カードと同じ場所へ置いたうえで、カード内側の点滅枠、`伏策待機中` badge、発動条件を強調表示する。クラス外枠、選択枠、プレイ可能発光とは別の内側表現を使う。
- 所有者が死亡した場合は発動しない。戦闘終了時に通常のカードinstanceへ戻し、ランデッキ上のカードを消失させない。
- 初期実装ではAttack／Skillカードだけに伏策を許可する。PowerとUnitは通常使用時の領域移動自体が機能の一部なので、許可する場合は別途所有規則を定める。

必要な新機構:

- 除外中カードへ付ける `ArmedTactic` 状態と安定したcard instance ID。
- 発動条件enumと、閾値を持つ条件parameter。
- ターン開始、敵Attack直前、現在コンボ到達の共通trigger hook。
- Resolving中も人間の選択だけを許可する `PendingTacticChoice`。
- 設置、提示候補、選択、発動、発動後移動を保存するjournal／リプレイ。

### 4.3 連環X

分類: **Tactician向けバフ／コンボのターン越境**

> ターン終了時、現在コンボを次のターンへ持ち越し、連環が1減少する。次のターンに最初に使用するカードは条件を問わずコンボを継続するが、コンボによるコスト軽減を受けない。

維持するもの:

- 現在コンボ数。
- 現在コンボ内のカード履歴と使用順。次ターンに終撃した場合、前ターンから続く同じコンボのAttackカードも終撃記録へ含める。

リセットするもの:

- 直前に使用したカードの元コスト。
- Wild／SuperWildによる次カード保護と、そのコンボ内のWild使用状態。

次ターンへの変換:

- 次ターンの `最大コンボ` は、持ち越した現在コンボ数から開始する。これにより乗勢Xも、その閾値を維持した状態で開始する。
- 持ち越したコンボ数までのコンボゲージは再獲得しない。次のカードで過去最高を超えた分だけ、新しいゲージを得る。
- エナジー、手札、カード使用回数は通常どおりターン更新する。連環はそれらを持ち越さない。
- 次ターンの最初のカードは元コストを問わず持越コンボへ加わる。ただしコンボ軽減は発生せず、黄色いコスト円にもならない。

境界:

- 連環はクラス全員の自動能力ではなく、Tacticianのカード、戦技、奥義、特性から付与するBuffとする。
- 連環Xは発動したターン終了時に、現在コンボが0でも1減少する。
- 余韻が同時にある場合、連環によるコンボ維持は発動したうえで、ターン終了時の連環減少だけを余韻が防げる。そのため次のターンにも再利用できる。
- 終撃で現在コンボを0にしていた場合も連環は発動し、0を持ち越して次ターン最初のカード用予約を作る。
- 正式なターン終了だけを対象とし、READYの設定・解除では発動しない。

名前候補:

- `連環`: 連鎖がターンをまたいで環のように続く。処理内容を最も連想しやすい。
- `布石`: 次ターンへ準備を残すタクティシャンらしさは強いが、コンボ維持だとは名前だけで分かりにくい。
- `継策`: 固有性はあるが造語感が強い。

現時点では `攪乱`、`伏策`、`連環` を三本柱とする。攪乱が敵の攻撃形式、伏策が時間差でのカード実行、連環が複数ターンのコンボ設計を担当し、旧遅滞は採用しない。

## 5. Enhancer

### 現在の状態

旧案の `伴奏`、Buff／Debuffを移す `転調`、状態を材料にする `触媒`、回復専用resourceの `調薬／備薬` は採用候補から外す。Enhancerは、Buffの時間を延ばす `余韻`、次の自身限定Buffを味方全体へ広げる `共鳴`、既存の回復・再生・復活を主に配布する方針を中核にする。

### 5.1 余韻

分類: **バフ**

> ターン終了時に減少または消滅する自身の他のバフが1つ以上ある時、それらを全て維持し、余韻が消滅する。

判定方法:

- 各Statusへ `余韻で延長可能` という個別metadataは付けない。
- 実際のターン終了処理で、そのBuffが減少または0になる予定かどうかから自動判定する。
- 対象は正のBuffだけとし、Debuffは保護しない。

保護する例:

- 元気、拡散など、ターン終了時に1減少するBuff。
- 護衛、守勢など、今回追加候補のターン終了時減少Buff。
- 将来追加される、ターン終了時減少または消滅型のBuff。

保護しない例:

- Barrier、耐性、継続、節制など、使用や特定イベントで減少するBuff。
- 洞察、加速、再生など、ターン開始時に効果を発揮または消費するBuff。
- 復活など、死亡時に消費するBuff。
- 永続Buff。
- Debuff。
- 余韻自身。

処理:

1. 正式なターン終了時、そのキャラクターのBuffが通常どおり変化した場合の結果を確認する。
2. ターン終了によって減少または消滅するBuffが1つ以上あれば、それら全ての変化を抑止する。
3. 保護に成功した後、余韻を消滅させる。
4. 該当Buffが1つもなければ、余韻は失わず次ターンへ残す。

境界:

- 複数の対象Buffがあれば、余韻1回で全てを同時に維持する。
- READY設定・解除では発動せず、全員READY後の正式なターン終了時だけ処理する。
- 対象Buffがターン終了時に効果を発生させる場合、その効果自体は通常どおり実行し、値の減少・消滅だけを抑止する。
- 余韻によって対象Buffの効果を余分に発動することはない。
- 初期仕様では `余韻1` の二値Buffとし、重複付与しても1を超えない案を推奨する。
- 対象Buffがない限り余韻自身は残るため、必要なBuffを後のターンに付与して利用できる。

### 5.2 共鳴X

分類: **Enhancer向け特殊バフ／Buff付与範囲の拡張**

> 自身のみに共鳴以外のバフが付与された時、付与された全てのバフを他の全ての味方に付与し、共鳴が1減少する。

基本処理:

1. 1つのBuff付与actionが、元の対象集合と付与するBuff groupを確定する。
2. 元の対象が共鳴保持者自身だけで、groupに共鳴以外のBuffが含まれるか確認する。
3. 元の対象へ通常どおり付与したうえで、同じgroupのうち共鳴以外のBuffを他の全生存味方へ付与する。
4. 共鳴を1減少させる。各対象の上限や実増加量は個別に判定する。

groupの扱い:

- `自身に筋力1・元気2・余韻を付与` のように1つのgroupへまとめたBuffは、共鳴1だけを消費して共鳴以外のgroup全体を他の味方へ付与する。
- JSON上で別のBuff actionなら別イベントとして扱う。共鳴が2以上あれば各actionで1ずつ消費できる。
- Debuff、回復、Block、Energy、カードコスト変更は共鳴の対象外。
- 発動者本人がgroup内のどのBuffも有効に受けられない場合は、共鳴を消費しない。
- 本人への対象Buff付与が成立した場合は、他の生存味方がいない時や、伝播先が付与上限に達している時でも共鳴を1消費する。

対象と再帰防止:

- 味方プレイアブルと召喚メイトの全てを含み、死亡・離脱済みactorは含まない。
- 元から複数対象または全生存味方が対象の付与では発動しない。
- 1つの付与eventは最大1回だけ全体化する。共鳴で追加された付与から別の共鳴を連鎖発動させない。
- 共鳴自身は全体化しない。同じgroupで共鳴と他のBuffが付与された場合は、他のBuffだけを広げる。
- 残光を全体化した場合、各actorは自分自身の終撃記録を参照する。記録がなければそのactorの残光は空打ちで消費される。

付与元とReady:

- カード、戦技、奥義、ポーション、レリック、特性、ターンtrigger、伏策、再演、残光など、正規のBuff付与eventなら発生源を限定しない。
- 過去の効果へは遡及しない。
- Planning中の全体化で新しい合法行動が生じた場合だけ、従来の規則で該当participantのREADYを解除する。Resolving中はPlanningへ戻さない。
- Xは残り発動回数であり、ターン終了では減少しない。

表示:

- 単体Buffの対象として共鳴保持者を選んだ時、味方全員を発光させて全体化を予告する。
- ログは `[共鳴] 筋力1・元気2 → 味方全体` のようにgroup単位で表示する。
- カードを人数分再表示せず、共鳴保持者から味方全体へ波が広がる演出を1回表示する。

### 5.3 回復・復活の配布方針

調薬／備薬は採用しない。新しい回復専用resourceを増やす代わりに、既存の回復機構と復活をEnhancerの明確な得意分野にする。

- 直接HP回復、再生、復活を付与する通常カードは、原則としてEnhancerのBasic／Rewardプールへ置く。
- 復活を保持できる対象はEnhancer本人に限定しない。Enhancerが他の味方へ復活を付与できる。
- ポーションとレリックによる回復・再生・復活はクラス外の例外として利用可能にする。
- 休息、イベントなどの戦闘外回復はクラス能力ではないため、この配布原則の対象外とする。
- 吸血はプレイヤー側が安定して取得できると強すぎるため、原則として敵専用Buffへ変更する。Coreへ陣営制限は設けず、敵データへ主に配布し、プレイヤー用通常カードから外す。
- `heal` action、再生、復活、吸血の実処理は既に存在するため、新しい戦闘ルールではなくカード・敵・ポーション・レリックの取得プールで制御する。

現時点のEnhancer固有新機構は `余韻` と `共鳴` の2つとし、回復・再生・復活は既存機構の配布によって第三のクラス軸にする。

## 6. 現在のクラス境界

| クラス | 現時点の固有操作 | 今回外したもの |
|---|---|---|
| Striker | 最大コンボを条件にする乗勢、コンボ終了、終了コンボの保存、残光による反復 | 単なる高打点だけの個性 |
| Guardian | Block持越し、他者へのBlock融通、防御成功によるGauge獲得 | 独立した共有防御pool、HPダメージの直接肩代わり |
| Tactician | 攻撃範囲の攪乱、除外へ仕込む時間差カード、コンボのターン越境 | 計画領域、山札上並べ替え、敵行動の遅滞 |
| Enhancer | Buffの維持、次の自身限定Buffの全体化、回復・再生・復活の提供 | 伴奏、転調、触媒、調薬／備薬 |

`再演` はStriker専用ではなく、条件付きで他クラスやUniversalカードにも配布できる汎用キーワードとする。ただし、最後の終撃コンボ全体を複数回繰り返す `残光` はStriker固有とする。

## 7. 表示文言確定前に残る境界

表示文言と詳細挙動は確定済み。乗勢は効果実行ごとに再判定し、余韻は維持対象がなければ残り、共鳴は本人への対象Buff付与が成立した時点で減少する。

連環のコンボ履歴持越しと直前コスト・Wild状態のリセット、堅持の無条件1減少、除外内で強化された伏策が強化後効果を使うことも既決事項として扱う。
