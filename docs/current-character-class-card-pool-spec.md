# キャラクタークラス・カードプール仕様

最終更新: 2026-08-20

この文書は、キャラクターピックとパーティ化に先行して実装する、キャラクタークラスとカード取得プールの現行仕様を定義する。

## 1. クラス

プレイアブルキャラクターのクラスは次の4種類とする。

- ストライカー (`Striker`)
- ガーディアン (`Guardian`)
- タクティシャン (`Tactician`)
- エンハンサー (`Enhancer`)

`Universal` はキャラクタークラスではなく、全キャラクターで共有するカードプールである。現行の `default` キャラクターはストライカーに属する。

## 2. カードの取得メタデータ

取得分類はカードJSONのルートに置き、カードのバージョンや強化状態から独立させる。

```json
{
  "id": "example_card",
  "poolKinds": ["Reward"],
  "poolClass": "Striker",
  "eligibleCharacterIds": ["default"]
}
```

- `poolKinds`
  - `Basic`: 初期デッキ用の基本カード。
  - `Reward`: 通常の取得候補へ出せるカード。
  - 両方を指定したカードは初期カードでありながら報酬にも出せる。
  - 空配列または省略時は通常プール外。メイト固有カードや特殊ドロップが該当する。
- `poolClass`
  - `Universal` または4クラスのいずれか。
  - `poolKinds` が空でなければ必須。
- `eligibleCharacterIds`
  - 空配列または省略時は、そのクラスの全キャラクターが取得可能。
  - 指定時は同じクラスに属する列挙キャラクターだけが取得可能。
  - Universalカードには指定しない。

カードIDの接頭辞は取得可否の判定に使用しない。強化前後および同じIDの複数コピーは同一の取得分類を共有する。

## 3. 取得元ごとの規則

- 通常戦闘のカード報酬とそのリロール: 操作キャラクターのクラスに属する `Reward` のみ。
- ショップ: クラス固有3枠とUniversal 2枠。片方が不足しても他方で補充しない。
- イベントの汎用カード報酬: Universalの `Reward` のみ。
- 明示カード付与イベント: イベントデータで指定したカードを直接付与できる。
- 初期デッキ: キャラクターデータに列挙したカードIDをそのまま使用する。`Basic` は自動混入を意味しない。
- メイトカード・敵加入カード: 通常プール外とし、固有ドロップ等の専用経路から取得する。

既存カードは、汎用性の高い報酬カードを各レアリティ4枚ずつUniversalへ移し、残りの報酬カードをストライカーへ分類する。`strike` と `defend` はUniversal Basic、`starter_block_0` と `starter_strike_2` はStriker Basic、ウィスプ関連カードは通常プール外とする。

## 4. 管理画面と検証

ゲームデータ管理画面では、キャラクターのクラス、カードの入手区分、所属プール、取得可能キャラクターを選択式で編集する。キャラクターIDは `id(名前)` 形式で表示する。

保存前および実行時に次を拒否する。

- 未知のクラス・入手区分
- 重複した入手区分・キャラクターID
- 通常プール外カードへの所属プールまたはキャラクター制限
- 所属プールなしの通常取得カード
- 存在しないキャラクター、または所属クラスと一致しないキャラクター制限
- Universalカードへのキャラクター固有制限

## 5. カード外枠のクラス表示

カードの所属プールは、全画面で共通カード部品の外枠色として表示する。

- ストライカー: 朱
- ガーディアン: 青緑
- タクティシャン: 紫
- エンハンサー: 黄緑
- Universal: 白金
- 通常取得プール外のメイト・トークンカード: 従来のカード種別外枠

カード種別はカード面の背景、レアリティは名称・イラスト・コスト装飾を担当し、クラス色とは別に維持する。プレイ可能表示は所属色の外枠を残した発光、選択状態は最優先の黄色外枠とする。

色値はClientの共通デザイントークンを唯一の定義元とし、ピック画面のクラス表示にも同じ値を使う。

## 6. パーティ基盤と後続フェーズとの境界

保存schema v8では、1～4人の個別所有状態を `RunState.PartyMembers` に保持できる。既存の単一キャラクター用フィールドは移行期間中のホスト互換ミラーとする。キャラクターピック画面と単一選択でのラン開始は実装済みだが、複数人の戦闘開始・終了処理が未接続のため、現時点の実動作は1人に制限する。詳細は `current-party-run-foundation-spec.md` を参照する。

後続では次を実装する。

- 1～4人の重複しないキャラクターピック
- 個別のHP、デッキ、ゴールド、レリック、ポーション、報酬、商店、休息、イベント選択
- 共通のマップ進行と戦闘。進行先はホストが決定
- 常に3枠のメイト召喚枠
- 人間所有のプレイアブルキャラクター全滅時の敗北
- ソロ複数人時の戦闘内CPU操作と、戦闘外での操作キャラクター切替
- 撃破者だけに提示する敵加入カードの専用報酬（戦闘開始時の敵のみ、最大4候補から1枚）
- ルーム共有、参加者認証、再接続、SignalR配信

戦闘中の操作担当切替は巻き戻しを起こさず、既に確定した行動には遡及しない。メイトは常にCPU操作とする。
